# Android and HarmonyOS notes

## Android

Finn Code is built and tested with Flutter 3.41.9 on Android API 35+. The Android project uses Kotlin, Material 3, and the default Flutter embedding.

The Android network security policy denies arbitrary cleartext traffic. Development exceptions are limited to emulator/local hosts so a local llama.cpp or Ollama server can be reached without weakening HTTPS enforcement for normal APIs.

## Emulator networking

The Android emulator maps the development machine to `10.0.2.2`:

```text
Host service:     http://127.0.0.1:11434
Emulator service: http://10.0.2.2:11434
```

The Codex WebSocket preset follows the same rule:

```text
ws://10.0.2.2:4500
```

A physical Android device uses the host machine's LAN address instead.

## OpenHarmony / HarmonyOS NEXT

The repository includes an `ohos/` project generated by the OpenHarmony Flutter fork. The current development machine reports an OHOS API 24 device and a working OHOS toolchain. A debug HAP build now reaches the signing step and stops cleanly because no DevEco signing material is committed; Android remains the release gate for this iteration.

Flutter is portable here because:

- screens and state use Flutter/Dart rather than Android views;
- HTTP and WebSocket adapters use `dart:io`, `http`, and `web_socket_channel`;
- navigation and layout are constraint-driven;
- platform secrets sit behind `SecretStore`.

The remaining work is package adaptation rather than a UI rewrite:

1. Provide or select an OHOS implementation for secure storage.
2. Verify `shared_preferences` registration on the chosen OHOS Flutter branch.
3. Build with the OHOS-enabled Flutter SDK and `flutter build hap`.
4. Test lifecycle, keyboard, safe areas, network policy, and secure storage on a real HarmonyOS device.
5. Add signing and distribution configuration.

Stock `flutter_secure_storage` is currently the Android-backed implementation. The `SecretStore` interface exists specifically to avoid leaking Android storage choices into the rest of the app.

## Verification commands

```bash
flutter analyze
flutter test
flutter build apk --debug
flutter test integration_test/app_test.dart -d <device-id>
```

For OHOS, use the OHOS Flutter toolchain rather than the stock SDK and follow the OpenHarmony-SIG setup for the matching engine revision. Open the `ohos/` project in DevEco Studio, configure a debug signing profile, and keep signing material out of Git before producing a signed HAP.
